### 教训: 论文速览后必须做代码审查
- **日期:** 2026-07-22
- **分类:** 有效模式 ✅
- **场景:** 阅读 GRaD-Nav 论文后直接做对比分析
- **问题:** 论文描述与代码实现存在多处关键差异（SqueezeNet 冻结、观测是 57D 向量而非图像、CENet vs VAE）
- **根因:** 论文写作有简化/美化倾向，代码是实现真相
- **教训:** 论文速览 → 代码审查 → 修正文档——三轮递进，不可跳过代码直接信论文
- **行动:** 任何论文分析都必须包含代码审查环节，文档留修正空间
- **关联:** @knowledge-pack-generator, change/grad-nav-code-review.md

### 教训: 多文件修改后做交叉一致性验证
- **日期:** 2026-07-22
- **分类:** 有效模式 ✅
- **场景:** 修改 5 个文档文件中的术语
- **问题:** 手动修改容易遗漏某些文件中的旧术语
- **根因:** 人脑不擅长追踪跨文件的一致性
- **教训:** 使用 grep 做交叉引用检查（术语一致性 + 引用链路完整性）
- **行动:** 任何涉及 3+ 文件的修改，完成后跑一次 grep 交叉验证
- **关联:** @output-reviewer, agent-usage-guide.md §三 模式2

### 教训: 计划与进度分开维护
- **日期:** 2026-07-22
- **分类:** 有效模式 ✅
- **场景:** 项目管理文档编写
- **问题:** 计划和进度混在一个文件里导致文档不可维护
- **根因:** 计划是静态蓝图，进度是动态日志——生命周期根本不同
- **教训:** MASTER_PLAN.md（写死不改）+ PROGRESS.md（活文档，随时更新）
- **行动:** 新项目启动时即分离计划文档和进度文档
- **关联:** agent-usage-guide.md §三 模式3

### 教训: 代码审查按逻辑顺序而非字母序
- **日期:** 2026-07-22
- **分类:** 有效模式 ✅
- **场景:** 审查开源项目 jxl_aiqiyi_xunlei
- **问题:** 按目录字母序读文件效率极低
- **根因:** 代码文件之间存在逻辑依赖，字母序破坏了这个依赖链
- **教训:** README → 核心算法 → 环境 → 模型 → 渲染 → 配置——这个顺序最有效
- **行动:** 审查任何新代码库时，先花 5 分钟规划阅读顺序
- **关联:** @modular-architect, agent-usage-guide.md §三 模式4

## 反模式 ❌

> 被验证有害的做法，必须避免。

### 教训: 不要让 Agent 一次做太多
- **日期:** 2026-07-22
- **分类:** 反模式 ❌
- **场景:** 要求 agent "审查整个代码库"
- **问题:** 输出超时或被截断，结果不完整
- **根因:** 单次 prompt 的任务量超过了模型的上下文处理能力
- **教训:** 一次只给一个具体任务。大任务必须拆分后才交给 agent。
- **行动:** 遵循 @modular-architect 的拆分原则——每个 Prompt = 一个模块
- **关联:** @modular-architect, agent-usage-guide.md §三 反模式1

### 教训: 不要让 Agent 同时修改多个不相关的文件
- **日期:** 2026-07-22
- **分类:** 反模式 ❌
- **场景:** 一次 agent 调用涉及多个独立改动
- **问题:** 不同改动的上下文交叉污染，产生不一致
- **根因:** Agent 在长上下文中容易丢失焦点（goal drift）
- **教训:** 一次 Agent 调用只做一类修改。不相关的改动分成多次调用。
- **行动:** 规划改动时检查——这些改动属于同一类吗？如果不是，分开处理。
- **关联:** @modular-architect, agent-usage-guide.md §三 反模式3

### 教训: 不要在没确认的情况下删除文件
- **日期:** 2026-07-22
- **分类:** 反模式 ❌
- **场景:** 发现"显然无用"的文件想删除
- **问题:** 所谓"显然"往往建立在不够完整的理解之上
- **根因:** 文件依赖关系可能隐藏在非显而易见的地方
- **教训:** 先列出待删文件清单并逐项确认，不要直接删除
- **行动:** 删除操作分两步——列表确认 → 确认后删除
- **关联:** agent-usage-guide.md §三 反模式4
