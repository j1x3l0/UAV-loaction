[核心数据点 — 与笔记行的对应]

1. 四旋翼模型参数 (Table I, p2):
   论文第160-173行的 Table I 列出了3寸/5寸的15个辨识参数。
   → 笔记 26-34 行: "被随机化的物理参数" 清单基于此表
   → 笔记缺失: k_x, k_y 等气动系数未列出; 实际电机常数 k_p1~k_p4 等非常具体
   → 笔记缺失: 3寸 k_omega=14.3 vs 5寸=27.1 (推力比≈1:2)

2. 随机化方案 — General Policy (Table II, p3):
   论文第220-229行的 Table II 定义了17个参数的均匀分布范围。
   → 笔记 32-34 行: "U(0.01,0.1), U(2,8), V(0.1,0.3), V(10,30)" 正确引用
   → 笔记行说"U(0,500)"实际是 omega_min 范围; "U(3000,5000)"是 omega_max
   → 关键设计原则 (论文p3行236-237): "Uniform distributions were designed to
     encompass parameters from both sizes" — 范围故意覆盖两台无人机

3. 随机化方案 — Fine-tuned (p3行238-244):
   论文原文: "each parameter is multiplied by U(1-p, 1+p), where p represents
   the randomization percentage"
   → 笔记 41-43 行: 对"%"含义的解释完全正确 (U(m0*0.9, m0*1.1) for 10%)
   → 笔记 51 行: "上界30%: 超过30%后性能下降太严重" — 论文未明确说"为什么是30%",
     但 Table III 数据支持: 30% fine-tuned 的 sim reward 已大幅下降

4. 策略架构 (§II-D, p3):
   论文行246-251: 3层FC, 每层64个神经元, ReLU, 20维输入, 4维输出
   → 笔记 171 行表格: "MLP (前馈)" 正确
   → 笔记缺失: 网络是 64x64x64 (比你们的128x128更小!)
   → 论文行262-265 (Fig.4): 他们尝试了加action history, state history,
     model parameters (ground truth 或含噪声), 全部没改善!
     这是重要发现 — Ferede 的结论与 Peng 相反 (Peng认为LSTM更好)

5. RL超参数 (§II-B, p2-3):
   论文行215-218: PPO, 100并行环境, gamma=0.999, max 1200 steps (12s),
   100M 总步数, Stable-Baselines3
   → 笔记未记录: gamma=0.999 (vs 你的0.99), 并行100环境 (vs 你的8)
   → 笔记未记录: reward = progress - c*||Omega||, collision=-10
     (进度奖励 + 角速率惩罚, 比你的7组件奖励简单得多!)

6. 仿真结果 (Table III, p4):
   论文第326-343行: General模型在3寸/5寸仿真中 crash rate 5.4%/1.2%
   Fine-tuned 模型完全不跨平台 (100% crash)
   → 笔记 19-24 行: "0%随机化失败, 增加随机化提高鲁棒性降低速度" 正确
   → 笔记缺失: 具体数字 — General 3寸 reward=64.67, 5寸=76.78
     Fine-tune 10% 3寸=77.59, 5寸=92.76 (确实是各自平台的最好表现)

7. 真机飞行结果 (Table IV/V, p6):
   论文第403-441行: 3寸: General 6.38m/s vs Fine-tune 10% 7.13m/s
                    5寸: General 7.83m/s vs Fine-tune 10% 8.63m/s
   → 笔记 23-24 行: "10%: 成功/最快" 正确对应
   → 笔记缺失: 具体的速度数值 (General比最优慢约10-15%)

8. 时间最优性 (§IV-D, p5-6):
   最优控制解: 理论单圈 1.07s, RL仿真 1.6s, 真机 1.9s
   作者结论: reward function 不够好, 应加入鼓励贴门框飞的项
   → 笔记未涉及此部分

[论文结构]

  §IV  (p3-5):   方法 — 任务 + 状态/动作 + DR + 自适应策略 (LSTM) + RDPG算法
  §V   (p5-7):   实验 — 架构对比 + 消融 + 鲁棒性
  §VI  (p7):     结论

[核心数据点 — 与笔记行的对应]

1. 随机化参数范围 (Table I, p5):
   论文第503-513行: Table I 列出了8类参数及其范围
   → 笔记 100-112 行: 参数表完整且准确!
   → 笔记 109 行 "物块质量 U(0.25*, 4.0*)" 正确, 但论文是绝对范围 [0.1, 0.4]kg
     (不是倍数, 笔记的"*标称倍数"标记稍有偏差 — 论文用的是绝对物理范围)

2. 每Episode固定原则 (§IV-C, p4):
   论文行335-338: "At the start of each episode, a random set of dynamics
   parameters mu are sampled...and held fixed for the duration of the episode."
   → 笔记 83-85 行: 完全正确的引用, 这是Peng的核心方法论
   → 笔记 89 行 "迫使策略学习隐式系统辨识" 是准确的解释
   → 论文行355-356: 两个例外 — action timestep 和 obs noise 每步都变
     (笔记207-209行已指出这一点)

3. LSTM vs FF 对比 (Table II, p7):
   论文第626-633行: LSTM 0.89, FF no Rand 0.0, FF 0.67, FF+Hist 0.70
   → 笔记 93-95 行: "Peng用LSTM" "你的策略是MLP" 正确
   → 笔记 170 行表格: "LSTM vs MLP" 对比正确
   → 笔记缺失: FF+Hist (带8步历史的FF) 在仿真中接近LSTM (0.87 vs 0.91),
     但在真机上差距拉大 (0.70 vs 0.89) — 说明LSTM的记忆机制比简单历史
     堆叠更有效地实现了系统辨识

4. 消融实验 (Table III, p7):
   论文第639-642行: 固定action timestep→0.29, 无obs noise→0.25,
   固定link mass→0.64, 固定puck friction→0.48
   → 笔记完全缺失此部分! 这是关键数据:
     - Action timestep 和 Obs noise 是最重要的随机化参数 (固定后暴跌)
     - Link mass 和 Puck friction 其次
     → 映射到你的A2: 这建议在Full噪声中, 时间步长和观测噪声应优先随机化

5. 鲁棒性测试 (§V-C, p7):
   论文行619-624: 在物块底部贴薯片袋改变接触动力学, LSTM策略仍达91%成功率
   → 笔记缺失此部分: 这是DR鲁棒性的有力证明

6. 网络架构 (§IV-F, p5-6):
   论文行452-482 + Fig.4: LSTM(128) + FF(128x2), 双分支架构
   → 笔记未涉及具体架构细节
   → 关键设计: feedforward分支直接接收s_t (绕过LSTM),
     保证当前状态能直接影响动作

7. 算法: RDPG + HER (§IV-E, p4-5):
   论文使用 DDPG (确定性策略) + HER (事后经验回放) + LSTM
   → 笔记 79 行说"PPO + LSTM" — 这是错的!
     论文用的是 RDPG (Recurrent DDPG), 不是 PPO!
     这是一个重要更正: Peng 用的是 off-policy DDPG + HER, 而非 on-policy PPO.

8. 训练配置:
   论文行487-553: MuJoCo, dt=0.002s, 100步/ep, batch=128 ep * 100步,
   ~8000 iterations, ~100M samples, ~8h on 100 cores
   → 笔记缺失

[最关键的差异: LSTM之争]

  Peng:    LSTM > FF+Hist > FF > FF no Rand (真机: 0.89 > 0.70 > 0.67 > 0.0)
  Ferede:  LSTM 无效, 简单MLP就够了 (Fig.4: 所有变体无显著差异)

  这为什么重要?
  → 你的项目目前用MLP (无记忆) — 如果Ferede是对的, 你不需要LSTM
  → 但如果你的噪声模式更像Peng (动力学随机化), LSTM可能有帮助
  → 这是一个待验证的开放问题

[必须修正]

1. 笔记第79行: "算法: PPO + LSTM" → 改为 "RDPG (Recurrent DDPG) + HER"
   Peng并未使用PPO, 而是基于DDPG的off-policy算法。

[建议补充]

3. Ferede的网络尺寸: 3层64神经元 (远小于你的128x128)
   → 你的128x128可能过大, 尤其对于噪声训练

4. Peng Table III 消融数据: Action timestep 和 Obs noise 是最关键的
   随机化参数 → 你的A2和A1已经做了obs noise, 但没做timestep noise

   → 你的奖励函数比论文复杂得多, 这是否必要?

6. Peng的"omniscient critic": 训练时Critic能看见真实动力学参数,
   Actor看不见 → 降低Critic方差, 但不泄露信息给Actor
   → 你可能可以在A2训练中使用类似技巧 (Critic知道真实sigma)

7. 笔记第109行: 参数范围应注为绝对物理值 (如[0.1,0.4]kg),
   而非"倍数" (论文Table I给的是绝对值)
