第一部分: self.state — 所有物理维度的源头
═══════════════════════════════════════════════════════════════════════════

self.state 是一个 6 维 NumPy 数组 [x, y, z, vx, vy, vz]。
它是整个观测系统的物理基础。它在两个地方被写入:

  ┌─────────────┬──────────────────────────────────┬─────────────────┐
  │ 写入点       │ 代码                              │ 触发时机         │
  ├─────────────┼──────────────────────────────────┼─────────────────┤
  │ reset()     │ self.state = [pos, vel]           │ episode 开始     │
  │ L173        │ pos = random([-9,-9,1], [2,2,2]) │                  │
  │             │ vel = [0,0,0]                    │                  │
  ├─────────────┼──────────────────────────────────┼─────────────────┤
  │ step()      │ self.state = new_state           │ 每个时间步       │
  │ L228        │ new_state = [new_pos, new_vel]   │ (dt = 0.05s)    │
  └─────────────┴──────────────────────────────────┴─────────────────┘

─── 维度 0-2: 位置 [x, y, z] ───────────────────────────────────────────────

  来源: self.state[:3]
  计算: 直接复制，无变换
  物理含义: 无人机在世界坐标系中的绝对位置
  单位: 米
  范围: x ∈ [-10, 10], y ∈ [-10, 10], z ∈ [0, 10]

  为什么是绝对值？
    → 障碍物是绝对坐标 [2,2,3] [6,3,5] [3,7,4]
    → 边界是绝对坐标 [-10,-10,0] 到 [10,10,10]
    → 网络需要知道自己在世界中的绝对位置来判断是否接近边界/障碍物

  在 step() 中的计算链:
    new_pos = pos + vel * dt + 0.5 * accel * dt^2   ← 半隐式 Euler 积分
    new_pos = clip_to_boundaries(new_pos)            ← 边界裁剪
    self.state = [new_pos, new_vel]                  ← 写回内部状态

  关键细节: 半隐式 Euler 使用 s = v0*t + 0.5*a*t^2 (匀加速精确位移)，
           而非 s = v_new * t (会多算位移)。dt=0.05, a=10 时，
           每步差 0.0125m，500 步累积差约 6m。


─── 维度 3-5: 速度 [vx, vy, vz] ───────────────────────────────────────────

  来源: self.state[3:6]
  计算: 直接复制，无变换
  物理含义: 无人机当前速度矢量
  单位: 米/秒
  范围: [-5.0, 5.0]（被 clip 限制）

  在 step() 中的计算链:
    thrust = action * self.max_thrust       → [-10, 10] N  (action ∈ [-1,1], max_thrust=10)
    accel  = thrust / self.drone_mass       → [-10, 10] m/s^2  (mass=1.0 kg)
    new_vel = vel + accel * self.dt         → 速度变化 ±0.5 m/s 每步 (dt=0.05)
    new_vel = np.clip(new_vel, -5.0, 5.0)  → 速度上限

  数值直觉:
    - 从静止加速到 5.0 m/s: 需要 5.0 / (10 * 0.05) = 10 步 = 0.5 秒
    - 每步速度最多变化 0.5 m/s
    - 穿越 20m 空间最短需要 4 秒 = 80 步

  边界反弹时的速度处理:
    if new_pos[i] <= boundary_min[i] or new_pos[i] >= boundary_max[i]:
        new_pos[i] = boundary   ← 位置被裁剪到边界
        new_vel[i] = -new_vel[i] * 0.5  ← 反向 + 50% 动能损失（非完全弹性碰撞）


─── 维度 6-8: 目标相对位置 [dx, dy, dz] ────────────────────────────────────

  来源: self.target_pos - self.state[:3]
  计算: target_dir = self.target_pos - pos  (向量减法)
        例如: target=[6,6,7], pos=[-8,-8,1]
        → target_dir = [14, 14, 6]
  物理含义: 从无人机指向目标的向量（原始位置差，非单位向量）
  单位: 米
  范围: pos ∈ [-10,10], target ∈ [5,8] → 每个分量 ∈ [-18, 18]

  为什么不是单位向量（与障碍物方向不同）？
    → 目标距离同时出现在维度 9（单独的距离标量）
    → "向量 + 标量" 的冗余编码让网络更容易学习
    → 不需要从 3D 向量隐式计算模长

  self.target_pos 的生成 (在 reset() 中):
    self.target_pos = self.np_random.uniform(self.target_min, self.target_max)
    范围: [5,8] × [5,8] × [2,8]
    目标永远在右上角的远角——起点到目标有足够距离保证任务难度


─── 维度 9: 目标距离 (标量) ─────────────────────────────────────────────────

  来源: ||self.target_pos - self.state[:3]||
  计算: dist_to_target = np.linalg.norm(target_dir)
  物理含义: 无人机到目标的直线距离
  单位: 米
  范围: 0 (到达) ~ 28m (理论最大, ||(-10,-10,0)-(8,8,8)|| ≈ 28)

  为什么维度 6-8 已有目标方向，还要单独一个距离？
    → 解耦设计：方向 + 距离分开编码
    → 网络通过维度 9 快速判断"还有多远"（标量比向量更易处理）
    → 显式给出距离让学习更快（不需要隐式学习计算模长）


─── 维度 10-12: 最近障碍物方向 (单位向量) ──────────────────────────────────

  来源: _get_obstacle_info(pos) 的返回值
  计算:
    (1) 遍历 3 个障碍物, 计算到每个的表面距离:
        dist = ||pos - obs_i|| - 1.0  (1.0 = obstacle_radius)
    (2) 取最近的那个:
        closest_obs = argmin(dist)
    (3) 计算方向并归一化:
        obs_dir = closest_obs - pos
        obs_dir_norm = obs_dir / (||obs_dir|| + 1e-8)

  物理含义: 从无人机指向最近障碍物的单位向量
  范围: 每个分量 ∈ [-1, 1]

  为什么是单位向量？
    → 只编码方向，与距离解耦
    → 如果直接用原始位置差，距离信息和维度 13 重复
    → 且数值范围不稳定（近处很小，远处很大）
    → 方向 + 距离分开编码 = 信息解耦，网络更容易学习

  为什么只取最近的障碍物，而不是 3 个？
    → 信息压缩: 3 个障碍物 = 9~12 维 → 1 个最近障碍物 = 4 维
    → 3 个静态障碍物的简单场景，"最近的"足以引导避障
    → 已知局限: 障碍物密集时此假设会失效

  为什么 + 1e-8？
    → 防止除零: 无人机恰好在障碍物中心时 obs_dir = [0,0,0]
    → norm = 0 → 不加 epsilon 会导致 [nan, nan, nan]


─── 维度 13: 最近障碍物距离 (标量) ─────────────────────────────────────────

  来源: _get_obstacle_info(pos) 的返回值
  计算: min(||pos - obs_i|| - 1.0, for all i)，且 max(result, 0.0)
  物理含义: 无人机表面到最近障碍物表面的距离
  单位: 米
  范围: [0, ~15]

  为什么 max(min_dist, 0.0)？
    → 无人机穿入障碍物内部时 dist - radius 为负
    → 裁掉负值，避免给网络输入它无法处理的负数距离概念
    → 负距离在物理上无意义（已经碰撞了）

def _get_observation(self):
    state_vector = self._build_state_vector()

    # 运行时统计（维护了但当前未用于归一化！）
    self.state_count += 1
    self.state_mean = ((self.state_count-1)*self.state_mean + state_vector) / self.state_count
    diff = state_vector - self.state_mean
    self.state_std = np.sqrt(((self.state_count-1)*self.state_std^2 + diff^2) / self.state_count)

    return state_vector.copy()  # 返回副本, 防止外部修改

  关键发现:
    → state_mean 和 state_std 被维护了，但观测并没有被归一化
    → 返回的是原始值，不是 (state - mean) / std
    → 这些统计是为未来准备的——Sim-to-Real 或域随机化时作为归一化参数
    → .copy() 是防御性编程，防止外部修改影响内部状态

def step(self, action):  # action ∈ [-1, 1]^3

    ┌─── 阶段 1: 动力学 ──────────────────────────────────────────┐

    thrust = action * self.max_thrust           # [-1,1]^3 → [-10,10]^3 N
    pos = self.state[:3]                        # 当前位姿 (上一帧的状态)
    vel = self.state[3:6]
    accel = thrust / self.drone_mass            # [-10,10]^3 m/s^2 (m=1.0)
    new_vel = vel + accel * self.dt             # 速度更新 (Euler 步)
    new_vel = np.clip(new_vel, -5.0, 5.0)      # 速度上限

    new_pos = pos + vel*self.dt + 0.5*accel*self.dt^2
    #             ^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^
    #             匀速位移            匀加速位移
    # 这是匀加速运动的精确位移公式 s = v0*t + 0.5*a*t^2
    # 而非简化版 s = v_new*t（会多算位移）

    ┌─── 阶段 2: 边界碰撞 ────────────────────────────────────────┐

    for i in range(3):  # x, y, z 三轴分别处理
        if new_pos[i] <= boundary_min[i]:
            new_pos[i] = boundary_min[i]       # 裁剪到边界
            new_vel[i] = -new_vel[i] * 0.5     # 反弹 + 50% 动能损失
        elif new_pos[i] >= boundary_max[i]:
            new_pos[i] = boundary_max[i]
            new_vel[i] = -new_vel[i] * 0.5

    恢复系数 0.5 的含义:
      → 非完全弹性碰撞
      → 撞墙后速度反向, 大小减半
      → 几次反弹后基本停下来

    ┌─── 阶段 3: 碰撞检测 ────────────────────────────────────────┐

    障碍物碰撞:
      for obs in self.obstacles:  # [2,2,3], [6,3,5], [3,7,4]
          if ||new_pos - obs|| <= 1.5:  # radius(1.0) + threshold(0.5)
              collision = True

    目标到达:
      reached_target = (||new_pos - self.target_pos|| <= 0.5)
      # 0.5m 阈值——距目标半米内算到达

    ┌─── 阶段 4: 状态更新 ────────────────────────────────────────┐

    self.state = [new_pos, new_vel]   # 6D 内部状态
    self.step_count += 1
    self._prev_action = action.copy() # 用于下一步的动作平滑奖励

    ┌─── 阶段 5: 奖励计算 ────────────────────────────────────────┐

    reward, components = self._compute_reward(
        state       = self.state,     # 刚更新的 6D 状态
        action      = action,         # 原始动作
        collision   = collision,
        reached_target = reached_target,
        target_distance = ||new_pos - target||
    )

    7 组件奖励 (详见 _compute_reward):
      r_dist    = -5.0 * (1 - exp(-0.3 * d))     ← 指数衰减, 越近梯度越大
      r_heading = speed * cos(angle) * 2.0         ← 朝目标方向加速
      r_obs     = -2.0 / (min_dist + 0.5)          ← 障碍物势场
      r_smooth  = -0.5 * ||a_t - a_{t-1}||         ← 动作平滑
      r_goal    = 100 + 50 * (remaining_steps/500) ← 到达 + 时间效率
      r_collision = -50.0 (if collision)           ← 碰撞惩罚
      r_timeout = -10.0 (if timeout)               ← 超时惩罚

    ┌─── 阶段 6: 返回观测 ────────────────────────────────────────┐

    return self._get_observation(), reward, terminated, truncated, info

    terminated = reached_target or collision
    truncated  = self.step_count >= 500  (500步 = 25秒真实时间)

第五部分: 数字直觉 — 一次 step() 的完整数值流
═══════════════════════════════════════════════════════════════════════════

  action (3D, [-1,1])
    │
    ▼  × max_thrust(10)
  thrust (3D, [-10, 10] N)
    │
    ▼  ÷ mass(1.0)
  accel (3D, [-10, 10] m/s²)
    │
    ▼  × dt(0.05)
  Δvel (3D, [-0.5, 0.5] m/s)       ← 每步速度最多变化 0.5 m/s
    │
    ▼  + vel
  new_vel (3D, clip to [-5,5])
    │
    ▼  × dt + 0.5 × accel × dt²
  new_pos (3D)
    │
    ▼  clip to boundaries
    ▼  check collision (dist ≤ 1.5m → collision)
    ▼  check target (dist ≤ 0.5m → reached)
    ▼  compute reward (7 components)
    │
    ▼  _get_observation()
  14D state vector

关键时间常数:
  - dt = 0.05s (20Hz 控制频率)
  - 加速到 5 m/s: 10 步 = 0.5 秒
  - 穿越 20m 空间: 最少 80 步 = 4 秒
  - episode 上限: 500 步 = 25 秒
  - 碰撞判定: 无人机表面距障碍物表面 ≤ 0.5m
  - 到达判定: 距目标 ≤ 0.5m

第七部分: 已知局限 & 改进方向
═══════════════════════════════════════════════════════════════════════════

  1. 状态未归一化
     state_mean/state_std 被维护但未使用。原始值的数值范围:
       位置 ∈ [-10,10], 速度 ∈ [-5,5], 距离 ∈ [0,28]
       → 不同维度量级不同, 网络需要隐式学习缩放

  2. 只编码最近障碍物
     3 个障碍物但只给 1 个的信息。密集障碍物场景会失效。
       → 扩展方向: 用注意力机制编码多障碍物, 或按距离排序取 top-K

  3. 障碍物方向在远距离时信息量低
     距离 > 10m 时, 障碍物方向几乎不变 → 提供的避障信号弱
       → 这也是依赖近距离势场奖励 (r_obs) 的原因

  4. 目标方向用原始向量而非单位向量
     维度 6-8 的数值范围取决于距离 → 靠近目标时信号变弱
       → 设计选择: 依赖维度 9 的距离标量来补偿

  5. 无历史信息
     14D 是纯瞬时观测, 没有速度历史或障碍物轨迹
       → Markov 假设: 当前状态足以决策。对静态障碍物成立,
         动态障碍物需要添加历史帧
