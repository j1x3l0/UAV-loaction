问题 4：基于代码分析无人机环境建模方法

4.1 动力学模型 — 简化欧拉积分

项目代码采用简化的解析运动学模型，使用欧拉积分法更新无人机状态：

self.position += self.velocity * dt
self.velocity += acceleration * dt

其中加速度由推力向量除以质量计算得到，未涉及旋转矩阵、空气阻力、风力扰动、电机动态等复杂因素。相比 Swift 论文中的高保真物理仿真（包含完整电机模型、Betaflight 低级控制器、电池模型和空气动力学模型），该模型做了大量简化。

4.2 状态空间建模 — 14 维完美传感器

使用 Gymnasium 的 Box 空间定义 14 维连续状态向量：

状态分量维度说明
position3无人机在三维空间中的位置坐标
velocity3三轴速度分量
relative_target_pos3目标相对于无人机的位置向量
target_distance1无人机到目标的欧氏距离
relative_obs_pos3最近障碍物相对于无人机的方向向量
obs_distance1无人机到最近障碍物的距离

状态通过完美传感器获取，无噪声、无延迟、无漂移。Swift 论文中，状态来自 VIO（视觉惯性里程计）+ U-Net 门框检测 + 卡尔曼滤波融合，存在显著感知噪声。

4.3 动作空间建模 — 3 维连续推力

self.action_space = spaces.Box(low=-1, high=1, shape=(3,), dtype=np.float32)

使用 3 维连续向量代表 x/y/z 三轴推力，通过 tanh 激活约束输出范围后乘以最大推力系数。Swift 论文使用总推力 + 三角速度（4 维），对应真实 FPV 遥控器的控制接口。

4.4 碰撞检测 — 球形碰撞模型

min_dist = np.linalg.norm(self.position - self.obstacles[i])
if min_dist < self.obs_radius + self.drone_radius:
    collision = True

采用球形碰撞检测，计算无人机中心与障碍物中心的欧氏距离，当距离小于两者半径之和时判定碰撞。障碍物均为静态球形，位置在 reset 时随机生成。

4.5 奖励函数建模 — 7 组件分层密集奖励

r(t) = r_dist + r_speed + r_obs + r_smooth + r_goal + r_crash + r_timeout
组件公式作用
距离引导 r_dist-5.0 * (1 - exp(-0.3 * d))指数衰减，近处梯度大、远处梯度小
速度方向 r_speedspeed * cos(theta) * 2.0鼓励朝目标方向飞行
障碍物势场 r_obs-2.0 / (min_dist + 0.5)距离越近惩罚越大，渐进式避障
动作平滑 r_smooth-0.5 * ||a(t) - a(t-1)||惩罚剧烈操作，保证飞行平稳
到达奖励 r_goal100 + 50 * remaining_ratio到达目标 + 时间效率奖励
碰撞惩罚 r_crash-50终止回合
超时惩罚 r_timeout-10达到最大步数时触发

与原始版本的 3 组件稀疏奖励相比，改进后的 7 组件密集奖励确保每个时间步都有非零信号，这是成功率从 0% 提升到 98% 的核心原因。

问题 5：Swift 论文提到的自主无人机竞速中的开放问题

基于 Swift 论文 (Kaufmann et al., Nature 2023) 的 Discussion 部分，自主无人机竞速领域面临以下主要开放问题：

5.1 感知鲁棒性不足

Swift 的感知系统假设环境外观与训练时一致。对光照变化、天气条件、赛道表面材质变化等缺乏适应能力。论文指出人类飞手受益于更高刷新率的摄像头（120Hz vs Swift 的 30Hz），这意味着 Swift 的视觉感知系统在信息采集速率和适应性上仍有显著差距。如何构建对环境变化具有鲁棒性的感知系统仍是一个未解决的问题。

5.2 坠机恢复能力缺失

Swift 一旦发生碰撞坠毁，整个回合即告终止，无法恢复继续飞行。而人类飞手可以全速坠毁后调整姿态继续比赛。在真实竞赛环境中，一次坠机并不意味着整场比赛结束。如何让自主无人机具备从异常状态中恢复的能力，是一个重要的工程和算法挑战。

5.3 竞争感知与博弈策略

Swift 不感知对手的存在，始终追求最快的单圈时间，不会根据比赛形势（领先/落后）调整策略。论文数据显示，Swift 40% 的失败是因为与对手碰撞。引入多智能体竞争感知和博弈策略是一个重要方向。在真实的竞速场景中，仅关注自身速度是不够的，还需要考虑对手位置、超车策略和防御策略。

5.4 Sim-to-Real 泛化能力

Swift 的残差建模方法需要针对具体赛道、平台和传感器配置重新采集数据（约 50 秒飞行 + 800-1000 个样本），迁移到新环境时需要重新标定。这种方法的泛化能力有限。论文明确指出，相较于广泛使用的域随机化方法，残差建模在需要精确控制的任务中更具样本效率，但两种方法的优劣对比和统一框架仍缺乏系统研究。

5.5 未知与动态环境的泛化

Swift 的赛道是预定义的固定赛道（7 个门框），门框位置和顺序已知。对于未知环境、动态障碍物、非结构化场景的泛化能力未经验证。从已知赛道到未知环境的迁移，从静态门框到动态障碍物的处理，都是需要进一步研究的方向。这与本课题"复杂环境三维路径规划"直接相关——当环境中出现移动障碍物、变化目标时，当前的策略是否能保持有效性。

5.6 从竞速到更广泛应用的迁移

论文在结论中提出，Swift 的混合学习方法（基于模型的感知 + 无模型的 RL 控制 + 残差建模 Sim-to-Real）能否推广到自主地面车辆、航空器和个人机器人等广泛领域，仍需验证。竞速场景具有明确的奖励信号（通过门框的进度）和有限的状态空间，而更广泛的应用场景可能面临稀疏奖励、高维状态空间和安全约束等更复杂的挑战。

5.7 与本课题的关联
