# Repository layout

本文档定义 `visual_rl` 的目录职责。整理工作以保持现有代码路径稳定为优先，
大型数据和第三方构建产物只做隔离，不纳入 Git。

## 当前目录职责

| 路径 | 职责 | Git 策略 |
| --- | --- | --- |
| `rlproject-swift-improved/` | 核心视觉强化学习实现 | 跟踪源码、测试和必要配置 |
| `docs/` | 当前有效的研究、平台和执行文档 | 跟踪 |
| `reports/` | 可复核的实验摘要和论文证据 | 只跟踪 README、聚合数据和关键图 |
| `grad_nav-main/` | GRaD-Nav 第三方参考实现 | 冻结，避免混入项目修改 |
| `better_vibe_coding/` | 开发方法与代码审查参考 | 冻结或后续归档 |
| `past/` | 历史代码、旧实验和资料 | 冻结，不作为当前实现入口 |
| `data/` | 3DGS、点云和训练数据 | 本地保存，不进入 Git |
| `PX4-Autopilot-1.17.0/` | 本地 PX4 源树和嵌套仓库 | 本地保存，不进入 Git |
| `.github/` | GitHub PR 模板和 CI | 跟踪 |

## 根目录规则

根目录仅保留项目入口和治理文件：`README.md`、`MASTER_PLAN.md`、
`PROGRESS.md`、阶段总结、协作规则、Git 配置以及上述一级目录。

以下内容不得提交：

- 数据集、点云和 3DGS 原始资产；
- PX4 源码副本、压缩包和构建树；
- 模型 checkpoint、日志、PID、缓存和本机 IDE 状态；
- 可由脚本重新生成且未被论文或总结引用的中间图片。

## 实验产物准入规则

一个实验目录只有满足以下至少一项时才应进入 Git：

1. 被 `PROGRESS.md` 或阶段报告引用；
2. 包含支撑结论的聚合 CSV/JSON；
3. 包含论文或评审需要的关键图；
4. 包含无法从现有配置重新构造的实验元数据。

日志、模型和完整逐回合输出应保留在本地或外部制品存储中。

## 后续整理顺序

1. 先维护本文件和目录清单，不改变运行路径；
2. 再筛选 `reports/` 中的可再生产物；
3. 然后归档 `past/` 和重复文档；
4. 最后才考虑移动核心代码或第三方目录，并同步修复路径和 CI。
